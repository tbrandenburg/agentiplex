# Release and packaging

From clean, current `main`, preview with `make release-plan bump=MINOR`, then publish with `make release bump=MINOR` (also PATCH or MAJOR). Highest stable vMAJOR.MINOR.PATCH tag is the baseline; no tags means v0.0.0, so the first MINOR release is v0.1.0. Prerelease tags are ignored. The preview reports the Helm `version` and `appVersion` changes without editing files. The release command uses the Go toolchain and Bash, updates both fields in `deploy/helm/agentiplex/Chart.yaml`, commits only that file when necessary, creates an annotated release tag on that commit (or current HEAD if already synchronized), and atomically pushes `main` and the tag. This requires permission to push directly to `main` and an atomic-push-capable remote; branch protection is never bypassed. Existing GitHub Actions tests, builds and publishes the release; stable packaging rejects chart metadata that differs from the tag. A failed push retains the local release commit and tag for manual inspection; check remote main and the tag before recovering, never force push. A newer unpublished stable tag blocks subsequent releases. No release is created by ordinary CI.
